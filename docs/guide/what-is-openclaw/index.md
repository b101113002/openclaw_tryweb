# 01｜認識 OpenClaw：它不是單純的聊天機器人

第一次接觸 OpenClaw，很容易把它想成「裝在電腦上的 ChatGPT」。更準確的理解是：**OpenClaw 是一套由你自行部署的 AI 助理系統，負責把聊天入口、模型、工作脈絡與工具串接起來。**

你可以在自己的電腦或伺服器上運行 Gateway，再讓不同聊天平台連到同一套服務。助理不只回答文字，也可能在你授權後讀取檔案、呼叫工具、執行程式或傳送訊息。因此，理解架構與權限，應該比急著安裝更多功能更優先。

## 先認識六個核心元件

| 元件 | 可以把它想成 | 主要責任 |
|---|---|---|
| Gateway | 中央交換站 | 維持服務、管理連線、路由訊息與工作階段 |
| Agent | 負責工作的助理角色 | 根據指示與上下文規劃、回應或呼叫工具 |
| Model／模型 | 文字與推理引擎 | 產生回覆、理解任務，部分模型可呼叫工具 |
| Channel／聊天渠道 | 你與助理對話的入口 | 例如 Telegram、Discord 或其他支援的平台 |
| Workspace／工作區 | 助理可使用的工作資料夾 | 放置角色設定、技能說明與經授權的工作資料 |
| Tools／工具 | 助理可以使用的能力 | 例如讀取檔案、搜尋、執行命令或控制其他服務 |

這些元件的名稱與可用功能可能隨 OpenClaw 版本調整，請以官方文件為準。

## 一則訊息如何變成一次助理任務？

以下是簡化後的概念流程：

```text
你從聊天平台或控制介面送出訊息
                 │
                 ▼
             Gateway
      驗證連線、辨識渠道與路由
                 │
                 ▼
               Agent
       讀取工作區與目前工作脈絡
                 │
          ┌──────┴──────┐
          ▼             ▼
       呼叫模型       需要時呼叫工具
          │             │
          └──────┬──────┘
                 ▼
        Gateway 整理並送回結果
                 │
                 ▼
          原本的聊天入口
```

實際內部流程可能包含工作階段管理、工具回合、記憶檢索及多 Agent 委派；這張圖只用來建立初步心智模型。

## OpenClaw 與一般雲端聊天服務有何不同？

| 面向 | 一般雲端聊天服務 | 自行部署 OpenClaw |
|---|---|---|
| 服務運行位置 | 通常由服務商維護 | 可在自己的電腦或伺服器運行 Gateway |
| 對話入口 | 主要使用服務商提供的 App／網站 | 可串接多種聊天渠道與控制介面 |
| 工具權限 | 由服務商產品設計決定 | 需要由部署者設定與檢查 |
| 模型選擇 | 依服務商提供的選項 | 可依支援情況設定雲端 Provider 或本機模型 |
| 維護責任 | 多由服務商承擔 | 你需要管理更新、備份、權限與服務狀態 |

自行部署並不等於所有資料必然留在本機。如果你使用雲端模型，送入模型的內容仍可能離開自己的裝置；若啟用外部搜尋、聊天平台或第三方插件，也會產生額外資料流向。

## 什麼情況適合使用？

- 希望從多個聊天平台使用同一個個人助理。
- 想建立能讀取指定檔案、整理資料或執行流程的工作助理。
- 想在自己的設備或伺服器管理 Gateway 與工作區。
- 願意花時間理解模型費用、工具權限與安全維護。

若只需要偶爾問答，單純使用一般聊天服務可能更簡單。OpenClaw 的價值在於可組合的工作流程與你能自行管理的部署方式；相對地，你也需要負起管理責任。

## 初學者最容易誤解的三件事

**1. 安裝成功，不代表模型已經可以使用。**  
OpenClaw 程式、Gateway 與模型服務是不同部分。你需要完成 Provider 認證或設定可連線的本機模型，才能收到模型回覆。

**2. 使用本機 Gateway，不等於完全離線。**  
聊天平台、雲端模型、搜尋服務與第三方工具都可能使用網路。請分別確認每一條資料路徑。

**3. Agent 能操作電腦，不代表應該一開始就給它所有權限。**  
先從低風險、可檢查的任務開始。讀取、寫入、執行 Shell、控制瀏覽器與對外傳訊息，應視為不同層級的授權。
