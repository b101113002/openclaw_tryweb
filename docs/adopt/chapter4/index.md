# 第 4 章｜連接聊天平台

完成本章後，你就能從手機或常用聊天平台與 OpenClaw 對話。

OpenClaw 可以透過內建渠道或外掛（Plugin）連接多種通訊服務。實際支援狀態與安裝方式可能隨版本改變，請以[官方渠道文件](https://docs.openclaw.ai/channels)為準。

| 渠道 | 特色 | 上游教材列出的整合方式 |
|---|---|---|
| 飛書／Lark | WebSocket 長連線，適合企業協作 | 內建 |
| 微信 | 透過第三方橋接方案連接 | 外掛／橋接 |
| QQ | QQ 開放平台 Bot API | 外掛 |
| WhatsApp | 透過 QR Code 配對 | 內建 |
| Telegram | Bot API，群聊與 Bot 功能完整 | 內建 |
| Discord | 支援伺服器、頻道與私訊 | 內建 |
| Slack | 工作區 App 與訊息互動 | 內建 |
| Signal | 透過 signal-cli 整合 | 內建 |
| Google Chat | Google Chat API／Webhook | 內建 |
| iMessage | 透過 BlueBubbles 或相容工具 | 內建 |
| IRC | 傳統 IRC 頻道與私訊 | 內建 |
| WebChat | Gateway 提供的網頁聊天介面 | 內建 |
| LINE | LINE Messaging API | 外掛 |
| Matrix | Matrix 開放通訊協定 | 外掛 |
| Mattermost | Bot API 與 WebSocket | 外掛 |
| Microsoft Teams | Teams SDK 整合 | 外掛 |
| Nostr | 去中心化通訊協定 | 外掛 |
| Twitch | IRC 連線 | 外掛 |
| Zalo | Zalo Bot API | 外掛 |

<details>
<summary>可以同時連接多個平台嗎？</summary>

可以。OpenClaw 可依渠道與對話來源路由訊息。例如，讓一個渠道處理工作通知，另一個渠道作為個人助理入口。不同渠道是否共用會話與記憶，仍取決於 Agent、Session 與路由設定；不要假設所有平台的對話內容會自動完全同步。

</details>

本章以**飛書／Lark**作為示範，因為原始教材有較完整的操作流程。飛書是第三方平台，不是使用 OpenClaw 的必要條件；若你不使用飛書，也可以直接選 Telegram、Discord、Slack 或 WebChat 等其他渠道。

## 1. 開始之前

請先確認：

- 已完成[第 2 章：手動安裝 OpenClaw](/adopt/chapter2/)及[第 3 章：初始設定精靈](/adopt/chapter3/)。
- 執行 `openclaw status` 時，Gateway 狀態正常。
- 已建立欲連接平台的帳號。
- 了解該平台的 Bot 權限、事件訂閱、資料政策及使用限制。

若你只是想先測試 OpenClaw，不一定要馬上接入聊天平台。可先使用本機 TUI 或 Dashboard，減少外部帳號與 API 權限設定。

## 2. 建立飛書／Lark 應用程式

以下流程以飛書開放平台的自建應用為例。飛書中國版與國際版 Lark 的網域及管理介面可能不同，請依實際帳號選擇正確平台。

### 步驟一：登入開放平台

- 飛書（中國版）：[飛書開放平台](https://open.feishu.cn/app)
- Lark（國際版）：[Lark Open Platform](https://open.larksuite.com/app)

使用對應的帳號登入。不要將登入憑證或 App Secret 提供給其他人。

<details>
<summary>使用國際版 Lark 的注意事項</summary>

若使用 Lark，請在 OpenClaw 渠道設定中使用 Lark 對應的網域選項（上游教材示例為 `domain: "lark"`）。請依目前 OpenClaw 版本文件確認欄位名稱與設定方式，不要直接將飛書中國版的設定照搬到 Lark。

</details>

### 步驟二：建立企業自建應用

在開放平台選擇建立企業自建應用，填寫應用程式名稱及用途說明，例如「OpenClaw 助理」，再建立應用。請只在自己的團隊或必要的測試範圍內開放應用，不要一開始就發布給所有組織成員。

### 步驟三：取得應用程式憑證

在應用程式的「憑證與基本資訊」頁面，取得 App ID 與 App Secret。App Secret 相當於密碼，請使用密碼管理工具或 OpenClaw 支援的安全憑證方式保存。不要貼到聊天、截圖、公開 GitHub Repository，亦不要寫入教學文章。

### 步驟四：啟用機器人能力

在應用程式的「添加應用能力」頁面，新增「機器人（Bot）」能力。請先完成這一步，再設定機器人訊息及事件相關權限；否則管理平台可能不會顯示對應權限項目。

### 步驟五：設定權限

進入「權限管理」，依照你要使用的功能選擇必要權限。

上游教材提供了一份包含訊息、文件、雲端硬碟、日曆、任務、多維表格、知識庫與白板等多種功能的權限清單。**不建議直接把整包權限全部開啟**，因為這會讓 Bot 取得遠超過基本聊天所需的資料存取能力。

建議分階段設定：

| 使用情境 | 權限方向 | 原則 |
|---|---|---|
| 僅收發機器人訊息 | 機器人訊息讀取、發送、群聊提及事件 | 先完成基本聊天 |
| 讀取使用者或群組資訊 | 必要的聯絡人及群組資訊讀取權限 | 只取得辨識對話對象所需資料 |
| 讀寫雲端文件 | 文件讀取、建立或編輯權限 | 只有要操作文件時才開啟 |
| 操作多維表格 | Base、Table、Record 等對應權限 | 依實際讀取／新增／更新需求選擇 |
| 操作日曆與任務 | 日曆事件、任務讀寫權限 | 不需要排程整合就先不開 |
| 搜尋文件或訊息 | 文件搜尋、訊息搜尋權限 | 評估是否真的需要跨資料搜尋 |

上游教材提及的權限類別大致包括：

| 權限前綴 | 功能 |
|---|---|
| `application:` | 應用程式管理與機器人選單 |
| `cardkit:` | 互動式訊息卡片 |
| `im:` | 訊息、群組、圖片及檔案資源 |
| `contact:` | 聯絡人及使用者基本資料 |
| `docs:`、`docx:` | 雲端文件 |
| `sheets:` | 試算表 |
| `base:` | 多維表格 |
| `calendar:` | 日曆及行程 |
| `task:` | 任務管理 |
| `wiki:` | 知識庫 |
| `drive:`、`space:` | 雲端硬碟與空間檔案 |
| `board:` | 白板 |
| `search:` | 文件與訊息搜尋 |
| `event:` | 事件及網路來源限制 |

若你只需要基本聊天，請從官方目前文件提供的最小訊息權限開始，再依測試結果逐項新增。上游教材舉例的訊息權限包含：

- `im:message`
- `im:message.p2p_msg:readonly`
- `im:message.group_at_msg:readonly`
- `im:message:send_as_bot`
- `im:resource`

這只是上游教材中的權限名稱範例，不保證在所有飛書／Lark 版本或應用類型中均完全相同。請以管理平台實際顯示與官方文件為準。權限名稱不應盲目整批貼上；若平台有權限說明，應逐項閱讀後再申請。

### 步驟五點五：設定可用範圍

在「可用範圍」或「應用發布 → 可用範圍」設定可以使用這個應用的帳號或部門。

- 個人測試：只加入自己的帳號。
- 小型團隊：只加入需要測試的成員或部門。
- 大型組織：先經管理者審核，再逐步擴大範圍。

若沒有設定可用範圍，即使應用程式已發布，其他使用者也可能無法在聊天平台中搜尋或加入機器人。

### 步驟六：建立版本並發布

前往「版本管理與發布」，建立版本、填寫版本說明，依組織流程送出審核。通過後，應用程式才會依其可用範圍生效。發布前請再次檢查權限與可用成員，不要因為方便而授予所有組織成員不必要的存取能力。

## 3. 在 OpenClaw 中新增飛書渠道

完成平台端應用設定後，回到安裝 OpenClaw 的電腦，執行：

~~~bash
openclaw channels add
~~~

依互動式提示選擇 Feishu／Lark，輸入 App ID 與 App Secret，其餘選項依你使用的版本及地區設定。

完成後重新啟動 Gateway，並檢查狀態：

~~~bash
openclaw gateway restart
openclaw gateway status
~~~

確認飛書渠道已成功連線。若狀態不是 connected，先查看日誌，不要反覆重新建立 App Secret。

<details>
<summary>CLI 參數設定方式</summary>

上游教材提供以 CLI 參數傳入憑證的方式。這種寫法可能將憑證留在 Shell history 或被本機程序觀察到，因此不建議在共享電腦上使用。優先採用互動式輸入或官方支援的 SecretRef／環境變數方式。

</details>

## 4. 設定事件訂閱

完成渠道設定並確認 Gateway 正在運作後，返回飛書開放平台，前往「事件與回調 → 事件配置」。

1. 選擇「使用長連線接收事件」。
2. 新增機器人接收訊息事件：`im.message.receive_v1`。
3. 儲存設定，並確認平台顯示連線成功。

<details>
<summary>為什麼上游教材使用 WebSocket 長連線？</summary>

Webhook 通常需要可被外部平台連線的公開 HTTPS 位址。WebSocket 長連線則由 OpenClaw 主動連接平台，適合沒有固定公網 IP 或網域的家用網路。

不過，長連線並不代表整個服務完全離線或完全本機化；訊息仍會經過聊天平台及模型供應商。請依資料敏感程度評估是否適合使用。

</details>

## 5. 配對與第一次對話

在飛書中找到機器人並傳送第一則訊息。若私訊政策採配對模式，機器人會回覆一組配對碼。

在終端機輸入：

~~~bash
openclaw pairing approve feishu PAIRING_CODE
~~~

配對碼的有效期限與格式可能依版本改變。核准前請先確認發送者身分，避免替陌生人開放你的 Agent。

配對完成後，就可以在聊天平台中與 OpenClaw 對話。建議先使用不含敏感資訊的測試任務，確認訊息收發、回覆對象及會話隔離都正常。

### 為什麼需要配對？

配對可以避免陌生人任意使用你的機器人。每次對話都可能消耗模型額度，也可能觸發具有檔案或外部服務存取權限的工具。只有通過核准的使用者，才能依你的 DM 政策正常使用。

## 6. 在群組中使用

將機器人加入群組後，通常可以透過 @ 提及觸發回覆。群組功能應先從小型測試群開始，再逐步開放。

<details>
<summary>群組存取政策（groupPolicy）</summary>

上游教材列出的 `groupPolicy` 常見策略如下，實際支援值請依目前版本確認：

| 策略 | 行為 |
|---|---|
| `open` | 允許所有符合條件的群組；仍可能要求 @ 提及 |
| `allowlist` | 只允許白名單中的群組 |
| `disabled` | 不處理群組訊息 |

原始教材示範以下設定方式：

~~~bash
openclaw config set channels.feishu.groupPolicy "open"
~~~

若要讓特定群組不必 @ 提及即可觸發，範例為：

~~~bash
openclaw config set channels.feishu.groups.GROUP_ID.requireMention false
~~~

將群組政策設為 open 或關閉 requireMention，會增加機器人接觸陌生訊息的機會。除非你已確認群組成員、工具權限與安全邊界，否則建議保留白名單及 @ 提及要求。

</details>

<details>
<summary>私訊存取政策（dmPolicy）</summary>

上游教材列出的私訊策略如下：

| 策略 | 行為 |
|---|---|
| `pairing` | 預設配對方式；新使用者需取得配對核准 |
| `allowlist` | 只允許 `allowFrom` 清單內的使用者 |
| `open` | 允許所有人；依設定可能需要在 `allowFrom` 加入萬用字元 |
| `disabled` | 停用私訊 |

若沒有明確需求，建議使用 pairing 或 allowlist，不要直接開放陌生人使用。

</details>

## 7. 各渠道的特色功能

不同聊天渠道可呈現的訊息格式與功能不相同。以下為上游教材所整理的部分特色；實際支援程度會隨 OpenClaw 版本及平台 API 改變。

### 飛書／Lark

- 以結構化卡片呈現需要人工確認的操作，部分流程可提供確認或拒絕按鈕。
- 可使用快捷操作卡片呈現常用功能。
- 部分版本支援在卡片中呈現 Agent 的執行狀態；請避免將內部推理或敏感內容直接公開給群組。
- 部分版本支援在特定會話中綁定 ACP 或子 Agent。

### Telegram

- 可依首則訊息產生討論話題名稱。
- 可支援論壇主題（Forum Topics）路由。
- 可調整錯誤通知的提示音行為。
- 傳送圖片前可能會檢查尺寸；不符合平台限制時改以檔案方式傳送。
- 對於 403 等權限錯誤，應檢查 Bot 是否已被移出群組或封鎖。

### Discord

- 可選擇以模型產生執行緒名稱。
- 部分版本會在訊息處理超時時回覆可見的錯誤提示。
- Gateway 的生命週期錯誤處理可能由統一機制管理。

### Slack

- 部分格式的富文字回覆可轉成按鈕或選擇器。
- 可依執行環境調整私訊、預覽與快取相關設定。

### WhatsApp

- 可辨識並抑制 Gateway 自己送出訊息所造成的群組回聲。
- 群組提及偵測及帳號關聯依 WhatsApp 連線狀態而定。

### Microsoft Teams

- 上游教材提及官方 Teams SDK 整合。
- 部分版本支援一對一訊息串流、歡迎卡片、提示啟動器、訊息編輯／刪除及 AI 標註。

## 8. 常見問題

**Q：事件訂閱無法儲存？**

先確認 Gateway 正在運作，並確認飛書／Lark 的長連線模式已啟用。平台可能會在儲存設定時檢查目前是否有應用程式連線。

**Q：機器人完全沒有回覆？**

依序檢查：

1. `openclaw status`：Gateway 是否正常運作。
2. `openclaw pairing list feishu`：發送訊息的使用者是否已完成配對。
3. `openclaw logs --follow`：查看即時日誌中的錯誤。
4. `openclaw gateway restart`：在確認設定正確後重新啟動。

**Q：平台權限審核沒有通過？**

確認你申請的權限是否超過實際需要，並依組織政策請管理者審核。不要為了通過審核而隱瞞應用程式實際需要的資料存取用途。

**Q：設定修改後沒有生效？**

先確認修改的是正確的渠道設定，再依官方文件判斷是否需要重新啟動 Gateway。可查看[附錄 G：設定檔詳解](/appendix/appendix-g/)。

**Q：在群組中 @ 機器人卻沒有回覆？**

確認群組政策不是 disabled；若使用 allowlist，請確認群組 ID 已加入白名單。也要確認平台已啟用機器人接收群組訊息所需的事件及權限。
